# Service workflows — master runbook

_Generated by `npm run docs:workflows` from `public/workflows.js`. Per-client runbooks (with progress flags) download from the Clients zone._

## Rules for AI agents and operators
- You are helping deliver a setup for a local business. Work ONLY with the placeholders in this runbook.
- Never ask for, guess, print or store a value behind a {{secret:…}} placeholder. Secrets stay in the client's encrypted vault and are used only by Bizzle's non-AI setup system.
- Never ask the client or operator to paste their information into this conversation. Refer to fields by placeholder (e.g. {{business.phone}}).
- Prefer invitations and limited roles over passwords. Never request an account owner's password.
- Every change needs a rollback step and the client's approval before it goes live.
- If a step needs information that is not listed as provided, stop and mark it "waiting on client".

## Security baseline (every engagement)
- [ ] We use invitations and limited roles instead of your passwords wherever a service allows it.
- [ ] Two-step verification (MFA) must be on for every account we connect.
- [ ] We only request the access a workflow needs, and we remove our access when setup is done unless you keep a care plan.
- [ ] Keys you give us are encrypted in your own workspace, never shown to our staff in our tools, and every use is logged for you.
- [ ] Nothing you enter here is sent to an AI service.
- [ ] Every change has a rollback plan, and you approve before anything goes live.

## Online booking

### Access needed (least privilege)
- **Booking page link** — client changes a setting (we give exact steps). Paste your public booking link under Links. No login needed.
- **Square access token (only if you want us to connect Square automatically)** — `{{secret:SQUARE_ACCESS_TOKEN}}` — optional, stored in client vault. Square Developer → your app → Production access token. Appointments + read-only locations scope.
- **Calendly personal access token (optional)** — `{{secret:CALENDLY_TOKEN}}` — optional, stored in client vault. Calendly → Integrations → API & Webhooks.

### Security checks
- [ ] Booking page served over HTTPS
- [ ] Collect only name, contact and appointment details
- [ ] Calendar access limited to booking calendars

### Steps
1. **[automated]** Add a "Book online" button to your site using your booking link
2. [manual] Configure services, durations and notice in your booking tool
3. [manual] Test booking end-to-end with you

**Verify:** A test booking appears on the business calendar and the customer gets a confirmation.

**Rollback:** Remove the booking button; your booking tool is unchanged.

## Missed-call text-back

### Access needed (least privilege)
- **Call forwarding** — client changes a setting (we give exact steps). We give you the exact forwarding setting for your phone provider; you switch it on.
- **Twilio Account SID** — `{{secret:TWILIO_ACCOUNT_SID}}` — optional, stored in client vault. Only if you use Twilio for texting. Twilio Console → Account info.
- **Twilio Auth Token** — `{{secret:TWILIO_AUTH_TOKEN}}` — optional, stored in client vault. Twilio Console → Account info. Use a restricted API key where possible.

### Security checks
- [ ] STOP/opt-out handling enabled
- [ ] Business texting registration (10DLC) in place
- [ ] No sensitive details sent by text

### Steps
1. [manual] Register / confirm the texting number
2. [manual] Set the missed-call text with your wording
3. [manual] You switch on call forwarding; we test together

**Verify:** A missed test call gets the text within a minute; replying STOP opts out.

**Rollback:** Switch off forwarding; texting stops immediately.
